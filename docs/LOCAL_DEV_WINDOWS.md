# llm-memory Local Development (Windows 11 Docker Desktop)\n\n## Quick Start\n\n### 1. Prerequisites\n\n```powershell\n# Check Docker Desktop is running\ndocker --version\ndocker-compose --version\n\n# Check Ollama running locally (on Windows)\nollama serve\n# In another terminal:\nollama list  # Should show models\n```\n\n### 2. Configure Environment\n\nCreate `.env.dev`:\n\n```bash\nDB_USER=postgres\nDB_PASSWORD=dev_password_123\nNODE_ENV=development\nLOG_LEVEL=debug\nOLLAMA_HOST=host.docker.internal:11434\n```\n\n### 3. Start Local Stack\n\n```powershell\n# Build and start all services\ndocker-compose -f docker-compose.dev.yml up --build\n\n# Or rebuild containers\ndocker-compose -f docker-compose.dev.yml up --build --force-recreate\n\n# Run in background\ndocker-compose -f docker-compose.dev.yml up -d\n```\n\n### 4. Verify Stack\n\n```powershell\n# Check all services running\ndocker-compose -f docker-compose.dev.yml ps\n\n# Check Agent health\ncurl http://localhost:3000/health\n\n# Check Postgres\ndocker-compose -f docker-compose.dev.yml logs postgres\n\n# Check Agent\ndocker-compose -f docker-compose.dev.yml logs agent\n```\n\n### 5. Test Agent\n\n```powershell\n# In PowerShell\n$body = @{\n    query = \"What's our naming convention?\"\n    topK = 3\n} | ConvertTo-Json\n\nInvoke-WebRequest -Uri http://localhost:3000/query `\n  -Method POST `\n  -Headers @{'Content-Type'='application/json'} `\n  -Body $body\n```\n\nExpected response:\n```json\n{\n  \"answer\": \"All microservices named {SomethingService}...\",\n  \"sources\": [{\"id\": \"policy-001\", \"excerpt\": \"...\"}],\n  \"latency_ms\": 125\n}\n```\n\n---\n\n## Development Workflow\n\n### Edit & Reload\n\n```powershell\n# Agent code is volume-mounted, auto-rebuilds\n# Edit src/agent.ts\n# Agent restarts automatically (nodemon or manual: docker-compose restart agent)\n\ndocker-compose -f docker-compose.dev.yml restart agent\n```\n\n### View Logs\n\n```powershell\n# All services\ndocker-compose -f docker-compose.dev.yml logs -f\n\n# Specific service\ndocker-compose -f docker-compose.dev.yml logs -f agent\ndocker-compose -f docker-compose.dev.yml logs -f postgres\n\n# Last 50 lines\ndocker-compose -f docker-compose.dev.yml logs --tail 50\n```\n\n### Database Access\n\n```powershell\n# Interactive psql\ndocker-compose -f docker-compose.dev.yml exec postgres psql -U postgres -d ai_memory\n\n# Or via host machine (port 5432 exposed)\npsql -h localhost -U postgres -d ai_memory -c \"SELECT * FROM architectural_policies;\"\n```\n\n### Clean Up\n\n```powershell\n# Stop services\ndocker-compose -f docker-compose.dev.yml down\n\n# Stop + remove volumes (⚠️ deletes data)\ndocker-compose -f docker-compose.dev.yml down -v\n\n# Stop + remove everything\ndocker-compose -f docker-compose.dev.yml down -v --rmi all\n```\n\n---\n\n## Troubleshooting\n\n### Ollama not accessible from Container\n\n```powershell\n# Check Ollama is running\nollama serve\n\n# Test from host\nInvoke-WebRequest -Uri http://localhost:11434/api/tags\n\n# Inside container, use host.docker.internal (Windows-specific)\ncurl http://host.docker.internal:11434/api/tags\n```\n\n### Postgres won't start (pgvector)\n\n```powershell\n# Check logs\ndocker-compose -f docker-compose.dev.yml logs postgres\n\n# Rebuild without cache\ndocker-compose -f docker-compose.dev.yml up --build --no-cache postgres\n\n# Use standard postgres image (pgvector added via extension)\n# See docker-compose.dev.yml: postgres:16-alpine includes pgvector support\n```\n\n### Agent can't connect to Postgres\n\n```powershell\n# Check DATABASE_URL in .env.dev\n# Should be: postgresql://postgres:dev_password_123@postgres:5432/ai_memory\n\n# Verify Postgres is healthy\ndocker-compose -f docker-compose.dev.yml ps postgres\n# Status should show \"healthy\"\n\n# Check network\ndocker network inspect llm-memory_llm-memory-net\n# Both postgres and agent should be connected\n```\n\n### Port already in use\n\n```powershell\n# Find process using port 3000\nnetstat -ano | findstr :3000\n\n# Kill it\ntaskkill /PID <PID> /F\n\n# Or use different port in docker-compose.dev.yml\n# Change: \"3001:3000\" for Agent\n```\n\n---\n\n## Performance Comparison: Local vs NAS\n\n| E2E Smoke Test\n\n```powershell\n# See scripts/test-policy-persistence.sh (bash script)\n# Can run in Windows via WSL or adapt to PowerShell:\n\n# Test script (PowerShell version)\n$env:AGENT_HOST = \"localhost\"\n$env:AGENT_PORT = \"3000\"\n\n# Load policy\nInvoke-WebRequest -Uri http://localhost:3000/policy `\n  -Method POST `\n  -Headers @{'Content-Type'='application/json'} `\n  -Body (@{\n    policy_file = \"./test-fixtures/naming_convention.md\"\n  } | ConvertTo-Json)\n\n# Query\n$response = Invoke-WebRequest -Uri http://localhost:3000/query `\n  -Method POST `\n  -Headers @{'Content-Type'='application/json'} `\n  -Body (@{\n    query = \"naming convention?\"\n  } | ConvertTo-Json)\n\n# Verify\nif ($response.Content -like \"*SomethingService*\") {\n  Write-Host \"✓ Policy persisted\"\n} else {\n  Write-Host \"✗ FAIL: Policy lost\"\n}\n```\n\n---\n\n## Next: Deploy to NAS\n\nOnce tested locally:\n\n1.
